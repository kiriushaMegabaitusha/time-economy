# Plan: TUI and Plain-Text Interface for Time Economy

## Overview
Create a Text User Interface (TUI) and a simplified plain-text interface for the Time Economy application to serve low-income communities with limited tech access.

## Current Features (from existing web app)
1. **Dashboard** - Stats, recent transactions, member balances, algedonic alerts, top skills
2. **Members** - CRUD, skill/want management
3. **Transactions** - Create, complete, dispute
4. **Needs** - Post, fulfill, close requests
5. **Governance** - Proposals, voting, status tracking
6. **Skills Directory** - Browse offered/wanted skills

## Goals
1. Build a rich TUI using `textual` for interactive terminal use
2. Build a minimal plain-text CLI for very low-tech environments
3. Both interfaces share the same SQLite database as the web app
4. Include offline data export/import for backup/sharing

## Implementation Plan

### Phase 1: Setup & Shared Components
- [ ] Add `textual` and `rich` to requirements.txt
- [ ] Create `app/tui/` package structure
- [ ] Create shared service layer for database operations (reuse existing)

### Phase 2: Plain-Text CLI (Simple First)
Create `app/cli.py` - a simple command-line interface:
```
python -m app.cli members list
python -m app.cli members add "John Doe" "john@example.com"
python -m app.cli tx create --from 1 --to 2 --hours 2.5 "Garden help"
python -m app.cli dashboard
python -m app.cli export --format csv
```

Features:
- Tabular output using simple text formatting
- No dependencies beyond SQLAlchemy
- CSV/JSON export for backups
- Interactive prompts when args missing

### Phase 3: Rich TUI (Full Interface)
Create `app/tui/app.py` using Textual:

**Screens:**
1. **DashboardScreen** - Grid layout with stats, alerts, recent activity
2. **MembersScreen** - DataTable of members, detail panel
3. **MemberDetailScreen** - Member info + skills/wants + transaction history
4. **TransactionsScreen** - List with filters, create form
5. **NeedsScreen** - Board view of open/fulfilled needs
6. **GovernanceScreen** - Proposal list with voting
7. **SkillsScreen** - Two-pane view (offered vs wanted)

**Widgets:**
- `MemberTable` - Sortable, searchable member list
- `TransactionLog` - Color-coded by status
- `BalanceChart` - ASCII/progress bar visualization
- `AlertPanel` - Algedonic signal display
- `CreateTransactionModal` - Form overlay
- `CreateMemberModal` - Form overlay
- `CreateNeedModal` - Form overlay
- `CreateGovernanceModal` - Form overlay

**Key Bindings:**
- `q` or `Ctrl+C` - Quit
- `1-7` or `F1-F7` - Switch screens
- `n` - Create new (context-dependent)
- `c` - Complete/dispute transaction
- `v` - Vote on governance
- `f` - Fulfill need
- `/` - Search/filter
- `r` - Refresh data
- `e` - Export data

### Phase 4: Low-Tech Plain Text Mode
Create `app/simple_cli.py` for extremely limited environments:
- Menu-driven (numbered options)
- One screen at a time
- Minimal screen clear/repaint
- Works on any terminal (including Windows CMD)
- No colors required

Menu structure:
```
=== TIME ECONOMY ===
1. View Dashboard
2. Members
3. Transactions
4. Needs Board
5. Governance
6. Skills
7. Export Data
0. Exit

Choice: _
```

## Technical Decisions

### Why Textual for TUI?
- Modern Python TUI framework
- Reactive data binding
- Built-in widgets (DataTable, Input, etc.)
- CSS-like styling
- Good documentation

### Why separate simple_cli?
- Some communities may have old computers
- Textual requires modern terminal with color support
- Simple CLI can run anywhere Python runs
- Backup/export is critical for low-tech users

### Database Sharing
- Both TUI and web app use same SQLite file
- No migration needed
- Can switch between interfaces seamlessly

## Export Formats for Low-Tech
1. **CSV** - Open in Excel/LibreOffice Calc
2. **JSON** - For tech-savvy backup
3. **Plain Text Report** - Printable member directory

Example plain text report:
```

================================

MEMBER BALANCES
---------------
Alice Johnson      +12.5 credits
Bob Smith          -3.0 credits  [CHECK-IN NEEDED]
```
